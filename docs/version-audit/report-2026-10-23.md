# Maintenance audit observations, 2026-10-23

The bounded audit for [#122](https://github.com/outside-labs/pocket-python/issues/122)
is ready for review. The current documentation describes Python 3.14.9; the
semantic oracle remains CPython 3.14.7 / Unicode 16.0.0. This work records
maintenance differences and independent engine boundaries. It does not adopt a
new oracle, language profile, module, browser capability or native ABI.

## Reproduction and identities

```sh
python runtime/check_version_audit.py --target matrix --report build/version-audit-matrix.json
python -m unittest discover -s tests -p test_version_audit.py -v
```

The environment needs the existing declared browser-tests group, an installed
Chromium, Node and CPython 3.14.7. No extra interpreter is installed by the audit.
[harness.md](harness.md) describes individual host commands and comparison rules.

The committed [observations.json](observations.json) was generated by the matrix
command, using **Node v24.19.0**, **Chromium 156.0.8078.4**, and **Playwright
1.64.0**. The oracle build identifies itself as `3.14.7 (main, Aug 5 2026,
10:29:49) [Clang 21.0.0 (clang-2100.1.1.101)]`. The snapshot retains the actual
unabridged build string.

Both hosts independently compiled the committed Python text through the existing
source runner/worker, explicitly requesting `core-source/1` and
`classes-source/1`. All runtime module hashes, compiler input source/bytecode
hashes, profile admissions, reference outcomes, later expectations and teardown
observations are in the snapshot. `checkout_commits` records the checkout before
this slice was committed; the snapshot's manifest, harness and engine hashes
identify the actual observed inputs, including this slice's local changes.

The engine modules are unchanged from base
`266c4fcc94773f2bae180d026d374bb035729d33`. The snapshot is evidence for that
source tree plus these audit files. It is not evidence for the concurrent
sequence/function changes or for a later merged main. After integration, rerun
the matrix and review any changed classifications before treating it as current.

## Observed results

All **12 pinned reference signatures matched**. Eight later-version expectations
remain source-backed and **not independently verified**: no installed 3.14.8 or
3.14.9 interpreter was available. The six excluded probes retain their reasons.
Small controls do not reproduce or validate the hazardous native defects.

| Outcome | Node | Chromium | Meaning |
| --- | ---: | ---: | --- |
| Source requests | 24 | 24 | Twelve programs in each of two explicit profiles. |
| Supported observations | 6 | 6 | Three unique unchanged control signatures, each in both profiles. |
| Explicit unsupported refusals | 6 | 6 | Template/bytes syntax; no application session is created. |
| Unavailable builtins | 4 | 4 | `format` and `reversed` raise `NameError`. |
| Denied imports | 4 | 4 | No StringPrep or IDNA module/grant was supplied. |
| Syntax rejections | 4 | 4 | Invalid source rejected; exact diagnostic contracts are separate. |
| Created sessions with measured zero teardown | 14 | 14 | Includes successful and failed execution paths. |
| Requests without a session | 10 | 10 | No measured teardown claim. |
| Reference / engine observation mismatches | 0 / 0 | 0 / 0 | Declared audit signatures held. |

The two hosts' compact observations agree, including compiled source/bytecode
fingerprints, errors and teardown. The 18 boundary observations per host carry
no compatibility credit; their expected occurrence does not make those Python
features supported. Nor are the six supported observations six maintenance
fixes: they cover three unique controls.

| Case | Both profiles on both hosts | Limit of the observation |
| --- | --- | --- |
| `list-delete-alias` | Matches `True 2 10 30` | Logical deletion and aliasing, not CPython array capacity. |
| `unicode-identifiers` | Matches `7 4` | Existing NFKC binding, not newer Unicode adoption. |
| `unicode-numeric` | Matches `True True` | Integer/float conversion equality; float display is separate. |
| `float-format-small` | Missing `format` builtin | Does not test near-`INT_MAX` precision or the security fix. |
| `dict-reverse-mutation` | Missing `reversed` builtin | No reverse-iterator behavior has been demonstrated in the engine. |
| `template-whitespace`, `template-debug` | Explicit tokenizer refusal | Pinned oracle strips trailing whitespace; later source expects preservation. |
| `stringprep-mapping`, `idna-mapping` | Import grant denied | Pinned oracle maps U+1E9E to `ss`; later source expects the original character. No library support claim. |
| `bytes-lookup-error` | Explicit bytes tokenizer refusal | Oracle raises `SystemError`; 3.14.9 source expects `ZeroDivisionError`. |
| `nonascii-syntax-range`, `obsolete-not-equal` | Syntax rejected | Rejection is not agreement with CPython's offset or suggestion changes. |

For the non-ASCII syntax range, CPython 3.14.7 reports character offsets
`12..15`; later regression source expects `8..11`. The engine reports its own
UTF-8 span `[1, 12, 1, 17]`. For `<>`, the pinned oracle reports `invalid syntax`,
whereas the later grammar adds a `!=` suggestion; the engine reports `Expected an
expression.` with span `[1, 4, 1, 5]`. These fields are preserved, not normalized
into an assertion of diagnostic compatibility.

Every created engine session had zero live frames at completion and closed with
zero **bytes, objects, roots, frames and external handles**. Compile refusals
reported no session, no application output and no fabricated zero counters.
These are logical engine counters. They do not measure native allocations or
garbage collection of the JavaScript heap. The existing browser harness closes
the browser/server and terminates each module worker after its response.

## Validation and issue disposition

The audit test suite covers oracle drift, source escape, duplicate IDs, promotion
of unexecuted expectations, reference disagreement, omitted/duplicate/foreign
engine responses, missing teardown, changed source/profile identity, fabricated
engine evidence, registry failures masquerading as refusals, cross-host input
drift, cross-host disagreement, and a real Node run. The existing reference
contract suite also passed locally. Browser and matrix results above came from
real Chromium; they are separate from test doubles used to exercise validation.

The audit's browser command is **standalone**. Existing CI runs the discovered
Python tests and the project's existing browser suite; this batch does not add
the matrix to CI or claim that existing browser jobs executed it. That workflow
integration would require a shared-file change outside this batch's ownership.

#122 is **open, with the audit batch ready for review and integration**. No issue
or Project fields were changed. After review and integration, the bounded audit
deliverable can be accepted with the documented limits. It does not justify
marking general Python 3.14.9 compatibility complete.

Remaining decisions are separate from this audit's implementation:

1. Before any oracle upgrade, authorize an available later interpreter and
   independently verify the eight source-backed expectations. Keep 3.14.7 until
   that tested decision.
2. Decide later semantic contracts when adopting reverse traversal, template
   strings, bytes/buffers, formatting or the relevant libraries. The current
   refusals, missing names and import denials do not decide those contracts.
3. Keep hazardous precision, compiler-depth and native-state probes explicitly
   unverified unless a separately bounded reference environment is approved.
4. Reconcile shared compatibility inventory or CI audit wiring only in the
   integrating workstream. No existing-file patch is required to run this audit.
